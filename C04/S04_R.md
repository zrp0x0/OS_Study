# S04. 프로세스의 생성

## Operations on Processes

### In UNIX-like O/S
- **PCB**: Register Info (Program Counter) + Process State + Process Resource Info 등 프로세스의 모든 정보 포함
- **Context Switch**
    - 현재 실행 중인 $P_1$의 정보를 저장
    - 실행할 $P_2$의 정보를 복원
    - Time Sharing을 통해 Concurrency(동시성)를 지원하여 동시에 여러 프로그램이 수행되는 것처럼 보이게 함

- 새로운 프로세스는 `fork()`라는 시스템 콜에 의해서 생성됨
- **자식 프로세스 (Child Process)**
    - 부모 프로세스의 주소 공간(Address Space)을 그대로 복사해서 생성됨 (A copy of the address space of the parent process)
    - 부모와 자식, 이 두 프로세스는 `fork()` 시스템 콜 호출 이후의 명령어부터 각각 독립적으로 계속 실행됨

- **부모와 자식을 구분하는 단 한 가지 차이점 (Return Code)**
    - 자식 프로세스에게는 반환값으로 **0**을 줌
    - 부모 프로세스에게는 **자식의 실제 PID (0보다 큰 양수)**를 반환함
    - (참고: `fork()`가 실패하여 프로세스 생성을 못 한 경우에는 -1을 반환)

### 예시 1: 기본적인 fork()
```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h> // wait() 시스템 콜을 위해 필요 (pid_t는 unistd.h에 포함된 sys/types.h에서 제공)

int main()
{
    pid_t pid;
    pid = fork();
    printf("Hello, Process %d!\n", pid);    
    return 0;
}
```
- **시나리오** - `fork()`를 호출 $\rightarrow$ 자식 프로세스 생성
    - 부모 프로세스가 `printf()`를 하고 종료 (예: `Hello, Process 12135!`)
    - 자식 프로세스가 `printf()`를 하고 종료 (`Hello, Process 0!`)
    - **주의**: 둘 중 누가 먼저 출력될지는 순서 보장이 안 됨 (운영체제 스케줄러가 Ready Queue에서 누구를 먼저 꺼내느냐에 따라 다름)

- **pid 값의 진실**
    - 부모에 찍히는 pid는 부모 자신의 pid가 아님 $\rightarrow$ **방금 태어난 자식의 pid**를 반환받은 것!
    - 자식에 찍히는 pid는 **0**
        - `fork()`는 한 번 호출되지만, 리턴은 총 두 번 일어남 (부모에게 한 번, 자식에게 한 번)
        - 부모의 Program Counter(PC)가 `fork()`가 끝난 시점을 가리킨 상태로 복사되었기 때문에, 자식도 `fork()` 내부에서 눈을 떠서 0을 반환받고 바로 다음 줄로 넘어감.
        - 만약 자식도 `fork()`를 처음부터 다시 실행한다면 무한 증식이 일어날 텐데, PC가 복사되기 때문에 그런 일은 발생하지 않음.

### 추가: 완전히 같은 프로세스를 fork하면 PCB만 만들어지는가?
- **논리적인 관점**: 자식 프로세스는 부모의 메모리(Text, Data, Heap, Stack) 공간과 똑같은 자신만의 독립적인 공간을 통째로 가져야 함
- **물리적인 관점 (OS 최적화 - Copy on Write)**: 
    - 진짜로 메모리를 다 복사하면 엄청난 오버헤드와 성능 문제 발생
    - `fork()` 직후에는 **새로운 PCB와 페이지 테이블(메모리 지도)**만 만들고, 실제 물리적 메모리는 부모와 자식이 공유하도록 연결만 해둠
    - 부모나 자식 중 누군가 데이터를 **수정(Write)**하려고 하면, 그제야 해당 메모리 페이지만 새로 **복사(Copy)**하여 독립시켜 줌
- **결론**: `fork()` 호출 시 OS는 새로운 PCB를 생성하고, 고유한 PID를 부여하며, 메모리를 가리키는 새로운 페이지 테이블을 만드는 작업을 확실하게 수행함.

### After a fork() system call
부모 프로세스는 계속 자신의 코드를 실행할 수도 있지만, 자식이 실행되는 동안 **`wait()` 시스템 콜**을 호출할 수도 있습니다.

- `wait()`를 호출하면 일어나는 일:
    - 부모 프로세스는 CPU를 반납하고 (Running 상태에서 벗어남), **Wait Queue (Waiting 상태)**로 이동함. (자식이 종료될 때까지 대기)
    - 자식 프로세스가 종료되면서 부모에게 인터럽트(SIGCHLD 시그널)를 보냄.
    - 인터럽트를 받은 부모는 Wait Queue에서 빠져나와 **Ready Queue (Ready 상태)**로 이동함.
    - 이후 스케줄러에 의해 Time sharing으로 리소스를 할당받으면 다시 코드를 이어서 실행함.

### 예시 2: wait()를 통한 순서 보장
```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main()
{
    pid_t pid;
    pid = fork();
    if (pid > 0) { // 부모 프로세스라면
        wait(NULL); // 자식이 끝날 때까지 대기
    }
    printf("Hello Process! %d\n", pid);
    return 0;
}
```
- **실행 결과**
    ```text
    Hello Process! 0       (자식 먼저 출력 후 종료)
    Hello Process! 18041   (대기열에서 깨어난 부모가 이어서 출력)
    ```
- 자식이 반드시 먼저 종료되고 부모가 실행되므로 **순서 보장이 됨!!**

### 예시 3: Copy on Write 확인
```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int value = 5;

int main()
{
    pid_t pid;
    pid = fork();

    if (pid == 0) { // 자식 프로세스
        value += 15; // 자식의 독립적인 메모리에서 15 더함 (이때 Copy-on-Write 발생)
        return 0; // 자식 종료
    }
    else if (pid > 0) { // 부모 프로세스
        wait(NULL);
        printf("Parent: value = %d\n", value);
    }
    return 0;
}
```
- **실행 결과**
    ```text
    Parent: value = 5
    ```
- **이유 분석**: 부모와 자식 프로세스는 논리적으로 완전히 서로 다른 메모리 공간을 가지게 됨. 자식이 값을 수정할 때 Copy-on-Write가 발생하여 부모의 원본 `value`에는 아무런 영향을 주지 않음.

### 프로세스 생성 개수 계산 (예시 4 & 5)

**예시 4: 순차적인 fork()**
```c
int main() {
    fork(); // 1 
    fork(); // 2
    fork(); // 3
    return 0;
}
```
- **생성된 전체 프로세스 수**: $2^3 = 8$개 (부모 1 + 자식 7)

**예시 5: 반복문 안의 fork()**
```c
int main() {
    int i;
    for (i = 0; i < 4; i++) {
        fork();
    }
    printf("Hello, Process!\n");
    return 0;
}
```
- **생성된 전체 프로세스 수**: $2^4 = 16$개
- (마지막 `printf`는 16개의 프로세스가 모두 실행하므로 문자열이 16번 출력됨)

### 예시 6: 헷갈리기 쉬운 반복문 출력
```c
#include <stdio.h>
#include <unistd.h>

int main()
{
    int i;
    for (i = 0; i < 4; i++) {
        pid_t pid = fork();
        printf("Hello, Process! %d\n", pid);
    }
    return 0;
}
```
- **예상 결과 분석**: 
    - 프로세스는 총 16개가 생성됨.
    - 하지만 `printf`가 루프 안에 있기 때문에, **루프가 돌 때마다 증식한 프로세스들이 계속 누적해서 출력을 실행**함.
    - `i=0`일 때 2번, `i=1`일 때 4번, `i=2`일 때 8번, `i=3`일 때 16번 출력됨.
    - 즉, 터미널에는 총 **30줄**(2 + 4 + 8 + 16)의 `Hello, Process!`가 마구 섞여서 출력됨.

### execlp("/bin/ls", "ls", NULL);
- 완전히 같은 일을 하기 위해서 프로세스를 새로 생성(`fork`)하는 일은 드묾. 보통은 전혀 다른 일을 시키기 위해 프로세스를 생성함.
- `fork()`로 프로세스를 생성하면 부모와 동일한 코드를 가지게 되는데, 여기에 새로운 프로그램을 덮어씌우는 역할을 하는 것이 `exec` 계열 시스템 콜임.

### 예시 7: execlp의 동작 원리
```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main()
{
    pid_t pid;
    pid = fork();

    if (pid == 0) {
        execlp("/bin/ls", "ls", NULL); // ls 프로그램으로 덮어씀
        printf("LINE J\n"); // 절대 실행되지 않음!
    }
    else if (pid > 0) {
        wait(NULL);
        printf("Child Complete\n");
    }
    return 0;
}
```
- **`printf("LINE J\n")`가 실행이 될까?** $\rightarrow$ **안 됨!!**
- **이유 분석**: `execlp`를 호출하는 순간 해당 프로세스의 메모리 공간(Text, Data, Heap, Stack)이 `ls` 프로그램의 내용으로 완전히 덮어씌워짐. 사실상 뇌를 갈아 끼우고 처음부터 다시 실행하는 것과 같으므로, 그 밑에 있던 기존 코드는 전부 날아가 버림.

### 예시 8: 자신의 진짜 PID 알아내기 (getpid)
- 자신이 방금 낳은 자식의 PID가 아니라, **나 자신의 고유 PID**를 알고 싶다면 `getpid()`를 사용함.
```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main()
{
    pid_t pid, pid1;
    pid = fork();

    if (pid == 0) { // 자식 프로세스 공간
        pid1 = getpid();
        printf("child: pid = %d\n", pid); // 자식이 반환받은 pid (항상 0)
        printf("my: pid1 = %d\n", pid1);  // 자식 본인의 진짜 pid
    }
    else if (pid > 0) { // 부모 프로세스 공간
        pid1 = getpid();
        wait(NULL);
        printf("child: pid = %d\n", pid); // 부모가 생성한 자식의 진짜 pid
        printf("my: pid1 = %d\n", pid1);  // 부모 본인의 진짜 pid
    }
    return 0;
}
```

### 주의사항
- `wait()`를 하지 않은 경우:
    - 부모가 먼저 출력될지 자식이 먼저 출력될지 절대 보장할 수 없음.
    - Ready Queue에 누가 먼저 들어가고 스케줄러가 누구를 먼저 뽑느냐에 달림.
    - 실행 중에도 타이머 인터럽트 등에 의해 빈번하게 Context Switch가 일어날 수 있으므로 명시적인 동기화(wait) 없이는 순서 보장이 불가능함.

### 정리
- **프로세스란?**: A program in execution (실행 중인 프로그램)
- **CPU Scheduler**: Time sharing을 통해 빠르게 Context Switch를 수행하며, 마치 여러 개의 프로세스가 동시에 실행되는 것(Concurrency)처럼 보이게 만듦.
- 메모리를 공유하지 않는 독립적인 프로세스 간에 협력하거나 데이터를 주고받으려면 **프로세스 간 통신 (IPC: Inter-Process Communication)** 기법이 필요함. (다음 챕터 주제)
