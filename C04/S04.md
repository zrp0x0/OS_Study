# S04. 프로세스의 생성

## Operations on Processes

### In UNIX0like O/S
- PCB: register info(Program Counter) + process state + process resource info + ...
- Context Switch
    - P_1의 정보를 저장
    - P_2의 정보를 복원
    - Time Sharing을 통해서 Concurrency Control을 수행 (동시에 수행되는 것처럼 보임)

- 새로운 프로세스스는 fork()라는 시스템 콜에 의해서 생성됨
- 자식 프로세는 
    - a copy of the address space of the parent process
    - 부모 프로세스의 공간을 그대로 복사해서 생성함

- 이 두 개의 프로세스는 계속 실행함
    - fork() 시스템 콜을 한 이후의 명령어를 실행함

- With one difference
    - the return code for the fork() is zero for the child process, whereas
    - the nonzero pid (bigger than zero) of the child is returned to the parent process
    - 즉, pid가 0이면 자식 프로세스이고
    - pid가 0보다 크면 부모 프로세스로 볼 수 있음

### 예시 1
```c
#include <stdio.h>
#include <unistd.h>
#include <wait.h> // 왜 이게 pid_t를 해주지? 근데 없어도 아무런 문제 없음

int main()
{
    pid_t pid;
    pid = fork();
    printf("Hello, Process %d!\n", pid);    
    return 0;
}
```
- 시나리오  
    - fork()를 호출함 => 자식 프로세스 생성
    - 부모 프로세스가 printf()를 하고 종료 (Hello Process 12135)
    - 자식 프로세스가 printf()를 하고 종료 (Hello Process 0)
    - 이거는 순서 보장은 안됨 (ready_queue에 들어가는 순서가 중요함)

- pid 값의 진실
    - 부모 프로세스에 찍히는 pid는 부모의 pid가 아님 => 자식의 pid를 반환받은 것!!
    - 자식 프로세스에 찍히는 pid 0
        - fork()는 반환을 총 두 개함 (바로 앞에 이야기한 자식의 pid / 0)
        - fork()가 되는 시점에서 원래 부모의 PC는 fork()가 끝난 시점을 가리키고 있고,
        - 이에 따라 자식에게 0을 주는 건 운영체제가 줌
            - 상식적으로 생각하면 fork()가 또 자식 프로세스에서 실행되면 무한 증식이 일어날 수 있기 때문임 (운영체제가 명시적으로 0을 반환해줌)

### 추가: 완전히 같은 프로세스를 fork하면 PCB만 만들어지는가?
- 논리적인 메모리는 전체가 복사됨
- 물리적인 메모리는 **처음에는** PCB와 메모리 지도(페이지 테이블)정도만 만들어짐
    - 논리적인 관점: 자식 프로세스는 부모의 메모리(Text, Data, Heap, Stack)공간과 똑같은 자신만의 독립적인 공간을 통째로 가져야함
    - 물리적인 관점(OS 최적화): 진짜로 메모리를 다 복사하면 성능 문제 발생 => Copy on Write 기법 사용
        - fork() 직후에는 새로운 PCB를 만들고, 부모의 메모리를 자식도 똑같이 가리키도록 연결만 둠 (메모리 공유)
        - 부모나 자식 중 누군가 데이터를 수정하려고하면(Write), 그제야 해당 메모리 부분만 새로 복사해줌(Copy)

- 결론적으로 fork() 호출 시 OS는 새로운 PCB를 생성하고, 고유한 PID를 부여하며, 메모리를 가리키는 새로운 페이지 테이블을 만드는 작업을 수행

### After a fork() system call
- 부모 프로세스는 계속 실행을 할 수 있거나
- 자식이 실행되는 동안에
    - wait() 시스템 콜을 하면
    - 부모는 ready_queue로 갔다가 wait_queue로 보냄 (??? 무슨 말이지?)
    - 자식이 종료될 때까지 기다리겠다는 의미
    - 자식이 종료되면 interrupt를 보내줌

### 예시 2
```c
#include <stdio.h>
#include <unistd.h>
#include <wait.h>

int main()
{
    pid_t pid;
    pid = fork();
    if (pid > 0) {
        wait(NULL);
    }
    printf("Hello Process! %d\n", pid);
    return 0;
}
```
- 실행 결과
```
Hello Process! 0
Hello Process! 18041
```
- 자식이 먼저 종료되고
- 부모가 종료되는 것을 확인할 수 있음!
- 이거는 순서 보장이 됨!! (위에는 안될 수도 있음)
- 자식이 종료되면 wait_queue에서 기다리고 있는 부모에게 종료되었음을 interrupt로 알려줌
- wait_queue에서 빠져나와서 ready_queue로 들어갔다가 time sharing으로 리소스를 받은 부모 프로세스가 실행됨

### 예시 3
```c
#include <stdio.h>
#include <unistd.h>
#include <wait.h>

int value = 5;

int main()
{
    pid_t pid;
    pid = fork();

    if (pid == 0) {
        value += 15;
        return 0;
    }
    else if (pid > 0) {
        wait(NULL);
        printf("Parent: value = %d\n", value);
    }
    return 0;
}
```
- 실행 결과
```
Parent: value = 5
```
- 이유 분석: 부모와 자식 프로세스는 완전히 서로 다른 메모리 공간을 가지게 됨 (Copy on Write)

### exclp("/bin/ls", "ls", NULL);
- 완전히 같은 일을 하기 위해서 프로세스를 새로 생성하는 일은 드묾
- 전혀 다른 일을 하기 위해서 프로세스를 새로 생성하는 일을 자주 함
- 예시
    - 배틀넷 런처를 실행 (a.out)
    - 업데이트 사항의 반영 여부 확인
    - 확인되면 b.out을 실행 아니면 업데이트 진행
    - 프로세스를 생성하려면 부모 프로세스가 생성시켜줘야함
    - 근데 프로세스를 fork()하면 부모와 동일한 메모리를 생성함
    - 여기서 새로운 b.out을 생성하고 싶다면?

- exclp에 있는 걸로 생성된 프로세스를 완전히 덮어씀

### 예시 7
```c
#include <stdio.h>
#include <unistd.h>
#include <wait.h>

int main()
{
    pid_t pid;
    pid = fork();

    if (pid == 0) {
        execlp("/bin/ls", "ls", NULL);
        printf("LINE J\n");
    }
    else if (pid > 0) {
        wait(NULL);
        printf("Child Complete\n");
    }

    return 0;
}
```
- printf("LINE J\n")가 실행이 될까?
    - 안됨!!

- 이유 분석
    - execlp를 호출하게 되면 부모와는 완전히 다른 프로세스 내용이 담기게 됨
    - 사실상 코드를 덮어쓰고 처음부터 다시 실행한다고 생각하면 됨

### 예시 8
- 자신의 pid를 알고 싶다면?
    - use getpid()
```c
#include <stdio.h>
#include <unistd.h>
#include <wait.h>

int main()
{
    pid_t pid, pid1;
    pid = fork();

    if (pid == 0) {
        pid1 = getpid();
        printf("child: pid = %d\n", pid); // 자식이 반환 받은 pid
        printf("my: pid1 = %d\n", pid1); // 자식 본인의 pid
    }
    else if (pid > 0) {
        pid1 = getpid();
        wait(NULL);
        printf("child: pid = %d\n", pid); // 생성한 자식의 pid
        printf("my: pid1 = %d\n", pid1); // 부모 본인의 pid
    }
    return 0;
}
```

### 주의사항
- wait()를 하지 않은 경우
    - 항상 부모가 먼저 출력된다는 보장할 수 없음!!
    - ready_queue에 누가 먼저 들어가는가가 중요함
    - 또는 실행 중에도 context switch가 일어날 수도 있기 때문에 항상 명시적인 순서를 보장하기 쉽지 않음
