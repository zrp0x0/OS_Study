# S03. 프로세스의 이해

## Process Concept

### 프로세스: 실행 중인 프로그램
- 운영체제 입장에서는 작업의 단위가 프로세스
- 하나의 프로세스가 실행되기 위해서 리소스가 필요함
    - CPU time
    - memory
    - files
    - I/O device

> 참고: 스토리지(SSD/HDD)에 있는 실행 파일을 다이렉트로 CPU로 가져와서 실행하지 못함. 따라서 메모리에 로드한 후 fetch해서 execute할 수 있음. 이런 상태에 있는 것을 프로세스라고 함.

> OS가 하는 기본적인 일은 바로 프로세스를 관리하는 것

### 여러 개의 섹션으로 나눠져있는 프로세스의 레이아웃
- Text Section
    - 실행 가능한 코드

- Data Section
    - 전역 변수

- Heap Section
    - 프로그램 실행 중 동적으로 할당되는 메모리

- Stack Section
    - 함수 호출 시 임시적인 데이터 저장소
    - 함수 파라미터, 리턴 주소, 지역 변수 등

- 전체적인 그림
    - 논리적인 0번지 (text)
    - data
    - heap - max로 커짐
    - 논리적인 max번지 (stack) - 0으로 커짐
    - <그림>

### 예시
```c
#include <stdio.h>
#include <stdlib.h>

int x;
int y = 15;

int main(int argc, char* argv[])
{
    int* values;
    int i;

    values = (int*)malloc(sizeof(int) * 5);

    for (i = 0; i < 5; i++) {
        values[i] = i;
    }

    return 0;
}
```

- 메모리 섹션 구조
    - argc, argv (stack section)
    - stack (stack section)
    - heap (heap section)
    - 초기화되지 않은 데이터 (data section)
    - 초기화된 데이터 (data section)
    - text (text section)

- 분석: size ./a.out
    ```
    text    data     bss     dec     hex filename
    1418     604      12    2034     7f2 ./a.out
    ```

### 프로세스가 실행됨에 따라 state가 변경됨
- 1. New: 프로세스가 막 생성된 상태
- 2. Running: 명령어가 실행되고 있는 상태
- 3. Waiting: 프로세스가 다른 이벤트 실행을 위해서 멈춰있는 상태
    - I/O completion or reception of a signal(such as interrupt)
- 4. Ready: waiting이 끝나고 프로세스가 프로세서에 할당되기 위해서 기다리는 상황
- 5. Terminated: 실행이 끝난 상태

### PCB(Process Control Block) or TCB(Task Control Block)
- 구조체를 하나 만듦 (PCB)
    - 프로세스가 가져야하는 모든 정보를 저장하자

- OS 시스템에서 각 프로세스는 PCB를 사용해서 표현함
- PCB가 가지고 있는 많은 정보 중 
    - Process State (new / running / waiting / ready / terminated)
    - Program Counter (어떤 명령어를 실행해야하는지 메모리 주소)
    - CPU Registers (include program counter)
        - program count + cpu register = context
    - CPU-Scheduling Information
    - Accounting Information
    - I/O Status Information

- OS는 PCBs를 가지고 있음 (list P_0, P_1, ..., P_n-1)

### A process is
- a program that performs a **single thread of execution**
- 싱글 쓰레드는 프로세스가 오직 한 번에 하나의 작업(task) 밖에 처리하지 못하게 함
- 현대 운영체제는 확장된 프로세스 개념을 가지고 있음
    - 하나의 프로세스가 여러 개의 실행 쓰레드를 가질 수 있게 함
    - 따라서 한 번에 여러 개의 작업을 수행할 수 있음
    - multi tasking 
    - multi processing
    - multi threading

- 프로세스 한 개 내에서도 여러 개의 쓰레드가 실행되어야하는 경우가 필요해짐

- A thread is a lightweight process
    - 주의: single thread of execution이라는 표현은 실행이 한 줄로 실행된다는 걸 의미
    - 이 용어에서 따와서 thread라는 개념이 생김
    - PCB를 통해서 하듯이 프로세스 안에서도 여러 개의 쓰레드를 여러 개 할 수 있지 않을까라는 생각에서 나옴

## Process Scheduling

### The Objective of multiprogrammign is
- to have some process running at all times (at the same time / concurrency vs parallel)
- 동시에 여러 개의 프로세스를 실행 시켜보자
- CPU 사용 효율을 극대화하고 싶기 때문!!

### The Objective of time sharing is
- to switch a CPU core among process so frequently
- 프로세스 간에 아주 빠르게 스위치를 해서 각 프로그램이 동시에 도는 것처럼 보이게 하자!!

### Scheduling Queues:
- 프로세스가 시스템에 들어가면, **ready queue**에 들어감
    - ready 상태거나 waiting이 끝나고 난 후에 execute가 되기 전에 들어감

- I/O가 있으면 **wait queue**에 들어감
    - 끝나면 ready queue로 들어감

- 실제 구현은 Linked List of PCBs

### Queueing Diagram
- as a common representaion of process scheduling

- ready queue로 들어가는 상황
    - I/O request -> i/o queue -> i/o ->
    - time slice -> 
    - fork a child -> child executes -> 
    - wait for an interrupt -> interrupt occurs ->

### Context Switch (문맥 교환)
- context: 프로세스가 사용되고 있는 상태 (PCB에 있는 정보)
- interrupt가 일어나면
    - running process의 current context를 저장하고
    - 다시 재개되어야 할 때 해당 context를 restore 할 수 있어야함

- context switch is a task that
    - CPU core를 다른 프로세스에게 넘겨주는 것
    - 1. 현재 프로세스 상태 저장하기
    - 2. 다른 프로세스 상태 복원하기

## Operations on Processes

### 운영체제 시스템이 제공해야만 하는 메커니즘
- 프로세스 생성
- 프로세스 종료

### 프로세스는 새로운 프로세스를 생성할 수 있음
- 새로운 프로세스를 만드는 프로세스: 부모 프로세스 (parent proecess)
- 만들어진 새로운 프로세스: 자식 프로세스 (child process)

### A tree of proceses
- init process: 모든 프로세스의 부모 프로세스 / 운영체제가 실행이되면 생성되는 가장 첫 프로세스
    - login
        - bash
    - kthreadd
        - khelper
        - pdflush
    - sshd
        - ...
    - ...

### Two possibilities for execution
- 부모랑 자식이 execute concurrently
- the parent waits until some or all of its children have terminated

### Two possibilities of address-space
- the child process is a duplicate of parent process
- 자식 프로세스가 부모 프로세스를 완전히 복사하는 경우
    - 굳이 별도의 프로세스 영역을 잡아줄 필요가 없음
    - 그냥 PCB의 정보만 다르면 됨!!

- the child process has a new program loaded into it
- 새로운 프로그램을 로딩하는 경우

### 예제
```c
#include <stdio.h>
#include <unistd.h>
#include <wait.h>

int main()
{
    pid_t pid;

    pid = fork(); // 자식 프로세스 fork

    if (pid < 0) { // error occured
        fprintf(stderr, "Fork Failed");
        return 1;
    }
    else if (pid == 0) { // child process
        execlp("/bin/ls", "ls", NULL); // ls를 실행하도록
    }
    else { // parent process (pid > 0)
        wait(NULL); // 자식 프로세스의 종료 하나를 기다림
        printf("Child Complete");
    }
    return 0;
}
```

### A process terminates
- 1. when it finishes executing its final statement
- 2. exit() system call: asks OS to delete it
- OS deallocates and reclaims all the resources:
    - allocated memories, open files, and I/O buffers, etc.

### Zombie and Orphan (좀비와 고아)
- zombie process: a process that has terminated
    - but whose parent has not yet called wait()
    - 자식 프로세스가 종료가 되었지만 부모가 아직 wait()를 호출하지 않은 상태
    - deamon, background process를 만들 때 사용함

- orphan process: a process that has a parent process
    - who did not invoke wait() and instead terminated
    - 즉, 부모 프로세스가 wait를 호출하지 않고 종료되어버린 상태 (고아 상태)
