## 1. Process Concept

### 프로세스 (실행 중인 프로그램)
운영체제 입장에서는 작업의 기본 단위가 프로세스입니다. 하나의 프로세스가 실행되기 위해서는 다음과 같은 **리소스(Resource)** 가 필요합니다.
* `CPU time`, `Memory`, `Files`, `I/O device`

> **💡 참고 사항**
> 스토리지(SSD/HDD)에 있는 실행 파일을 다이렉트로 CPU로 가져와서 실행하지 못합니다. 따라서 **메모리에 로드한 후 fetch해서 execute**할 수 있으며, 이런 상태에 있는 것을 **프로세스**라고 합니다.
> **OS가 하는 기본적인 일은 바로 프로세스를 관리하는 것입니다.**

### 여러 개의 섹션으로 나누어져 있는 프로세스의 레이아웃

| 섹션 (Section) | 저장 내용 | 특징 및 방향 |
|---|---|---|
| **Stack** | 함수 호출 시 임시 데이터 (파라미터, 리턴 주소, 지역 변수 등) | 논리적 Max 번지에서 **0으로 커짐 (아래로)** |
| **Heap** | 프로그램 실행 중 동적으로 할당되는 메모리 | **Max로 커짐 (위로)** |
| **BSS** | **초기화되지 않은** 전역 변수 | |
| **Data** | **초기화된** 전역 변수 | |
| **Text** | 실행 가능한 코드 | 논리적인 0번지 |

**[예시 코드 및 메모리 분석]**
```c
#include <stdio.h>
#include <stdlib.h>

int x; // BSS section
int y = 15; // Data section

int main(int argc, char* argv[])
{
    int* values;
    int i;

    values = (int*)malloc(sizeof(int) * 5); // Heap section

    for (i = 0; i < 5; i++) {
        values[i] = i;
    }

    return 0;
}
```
* **메모리 구조**: `argc/argv` & `stack` (Stack) -> `heap` (Heap) -> `초기화 안된 데이터` (BSS) -> `초기화된 데이터` (Data) -> `text` (Text)
* **바이너리 사이즈 분석 (`size ./a.out`)**
```text
text    data     bss     dec     hex filename
1418     604      12    2034     7f2 ./a.out
```

### 프로세스 상태 (Process State) 변화
프로세스가 실행됨에 따라 상태가 변경됩니다.

1. **New**: 프로세스가 막 생성된 상태
2. **Ready**: waiting이 끝나고(또는 생성 직후) 실행될 준비를 마치고 CPU 할당(Dispatch)을 기다리는 상태
3. **Running**: 명령어가 실행되고 있는 상태
4. **Waiting (Blocked)**: 프로세스가 I/O 등 다른 이벤트 완료를 기다리며 CPU를 반납하고 멈춰있는 상태
5. **Terminated**: 실행이 끝난 상태

### PCB (Process Control Block) / TCB (Task Control Block)
프로세스가 가져야 하는 모든 정보를 커널(Kernel) 메모리 공간에 저장하는 구조체입니다. OS 시스템에서 각 프로세스는 이 PCB를 사용해서 표현되며, OS는 PCB 리스트(`P_0, P_1, ..., P_n-1`)를 관리합니다.

**[PCB에 포함되는 주요 정보]**
* **Process State**: 상태 정보 (new / running / waiting / ready / terminated)
* **Program Counter**: 어떤 명령어를 실행해야 하는지 가리키는 메모리 주소
* **CPU Registers**: PC 포함, 프로세스가 다시 실행될 때 필요한 모든 상태 정보 (**Context**)
* **CPU-Scheduling Information**
* **Accounting Information**
* **I/O Status Information**

### 프로세스와 쓰레드 (Process & Thread)
* 프로세스는 기본적으로 **Single thread of execution**(한 번에 하나의 작업만 처리)을 수행하는 프로그램입니다.
* **현대 운영체제의 확장된 프로세스 개념**: 하나의 프로세스가 여러 개의 실행 쓰레드를 가질 수 있게 하여, 한 번에 여러 작업을 수행(`multi tasking`, `multi processing`, `multi threading`)할 수 있도록 지원합니다.
* **Thread**: 가벼운 프로세스(**lightweight process**)
  > *single thread of execution*이라는 표현은 '한 줄로 실행된다'는 것을 의미하며, 여기서 *thread*라는 개념이 파생되었습니다. "PCB를 통하듯 프로세스 안에서도 쓰레드를 여러 개 관리할 수 있지 않을까?"라는 생각에서 탄생했습니다.

## 2. Process Scheduling

### 스케줄링의 목적
* **Multiprogramming**: 동시에 여러 개의 프로세스를 실행시켜(Concurrency vs Parallel) **CPU 사용 효율을 극대화**하기 위함. (항상 프로세스가 돌고 있도록)
* **Time Sharing**: 프로세스 간에 CPU Core를 아주 빠르게 스위칭하여, 각 프로그램이 **동시에 도는 것처럼 보이게** 하기 위함.

### 스케줄링 큐 (Scheduling Queues)
실제 구현은 PCB의 Linked List 형태로 이루어집니다.
* **Ready Queue**: 시스템에 진입했거나 waiting이 끝난 후 실행 대기 중인 큐
* **Wait Queue (I/O Queue)**: I/O 작업이 필요한 경우 들어가는 큐 (완료 시 Ready Queue로 이동)

### Queueing Diagram
프로세스 스케줄링의 일반적인 표현으로, **Ready Queue로 들어가는 4가지 상황**은 다음과 같습니다.
1. `I/O request` -> `I/O queue` -> `I/O 수행` ->
2. `Time slice 만료` -> 
3. `Fork a child` -> `자식 실행` -> 
4. `Wait for an interrupt` -> `인터럽트 발생` ->

### 문맥 교환 (Context Switch)
* **Context**: 프로세스가 사용되고 있는 상태 (PCB에 있는 정보)
* **인터럽트 발생 시**: Running 중인 프로세스의 현재 context를 저장하고, 추후 재개 시 복원(restore)할 수 있어야 합니다.
* **Context Switch 메커니즘**:
  1. 현재 프로세스 상태 **저장**
  2. 다른 프로세스 상태 **복원**
  > **⚠️ 주의 (Overhead)**: CPU Core를 다른 프로세스에게 넘겨주는 이 컨텍스트 스위칭 시간 동안, CPU는 유용한 작업을 전혀 하지 못합니다.

## 3. Operations on Processes

운영체제 시스템은 **프로세스 생성**과 **프로세스 종료** 메커니즘을 반드시 제공해야 합니다.

### 프로세스 생성 (부모와 자식)
* **Parent process**: 새로운 프로세스를 만드는 주체
* **Child process**: 생성된 새로운 프로세스
* **init process**: OS가 실행되면 생성되는 **가장 첫 프로세스**이자, 모든 프로세스의 최상위 부모 (예: `init` -> `login` -> `bash`)

### 자식 프로세스 생성 시 2가지 옵션

| 구분 | 옵션 1 | 옵션 2 |
|---|---|---|
| **실행 방식 (Execution)** | 부모와 자식이 동시에 실행 (Concurrently) | 부모가 자식이 종료될 때까지 대기 (Wait) |
| **주소 공간 (Address-space)** | 부모 프로세스를 **완전히 복사** (PCB 정보만 다름) | **새로운 프로그램**을 로딩하여 덮어씀 |

**[프로세스 생성 예제]**
```c
#include <stdio.h>
#include <unistd.h>
#include <wait.h>

int main()
{
    pid_t pid = fork(); // 자식 프로세스 생성 (fork)

    if (pid < 0) { // 생성 실패
        fprintf(stderr, "Fork Failed");
        return 1;
    }
    else if (pid == 0) { // 자식 프로세스인 경우
        execlp("/bin/ls", "ls", NULL); // ls 명령어 프로그램으로 덮어씀
    }
    else { // 부모 프로세스인 경우 (pid > 0)
        wait(NULL); // 자식 프로세스의 종료를 기다림
        printf("Child Complete");
    }
    return 0;
}
```

### 프로세스 종료
1. 마지막 명령문(statement)을 실행 완료했을 때
2. `exit()` 시스템 콜 호출 시 (OS에 삭제 요청)
* **종료 시 OS의 역할**: 할당된 메모리, 열린 파일, I/O 버퍼 등 모든 리소스를 할당 해제(Deallocate)하고 회수(Reclaim)합니다.

### 좀비(Zombie)와 고아(Orphan) 프로세스
| 상태 | 정의 및 문제점 | OS의 처리 방식 |
| :--- | :--- | :--- |
| **좀비 (Zombie)** | 자식은 종료되었으나, 부모가 아직 `wait()`를 호출하지 않은 상태 | 모든 프로세스는 종료 시 잠깐 좀비가 되며, 부모가 `wait()`를 호출해야 완전히 소멸. (데몬/백그라운드 프로세스 생성 시 응용) |
| **고아 (Orphan)** | 부모 프로세스가 `wait()` 호출 없이 먼저 종료되어 버린 상태 | 현대 운영체제(Linux 등)에서는 최상위 `init` 프로세스(PID 1)가 고아들을 입양하여 주기적으로 `wait()`를 호출해 정리함. |
